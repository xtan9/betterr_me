# Expose the Household Runway Interview through a Runtime

The Household Runway Interview exposes a framework-neutral Runtime instead of making callers orchestrate its reducer protocol. Its public contract consists of `getSnapshot()`, `subscribe(listener)`, idempotent `start()`, `send(intent): void`, and idempotent `dispose()`. Construction is side-effect-free, the immutable snapshot is presentation-neutral, and `send` accepts only user intents. The Runtime owns restoration and draft conflicts, state transitions, effect execution, concurrency and stale-result checks, destructive-action policy, and validated browser-history projection. The reducer, draft schema and migrations, operations, effects, events, transition metadata, and adapter outcomes remain internal. A supported browser/React adapter injects narrow capabilities and gives UI code only the snapshot and intent dispatcher; React continues to own markup and localization.

## Considered Options

- Keep the caller-orchestrated pure reducer and remove only unused exports.
- Move orchestration into a React-specific controller.
- Put a framework-neutral Runtime around the internally pure state machine.

The first option leaves callers coupled to operation and effect lifecycles despite a smaller-looking export list. The second hides those lifecycles but binds the Interview boundary to one UI framework. The Runtime preserves deterministic internals while concentrating lifecycle knowledge behind a reusable seam.

## Consequences

- Public intents express only user actions. Clocks, IDs, autosave triggers, browser events, adapter outcomes, retries, and success or failure protocol messages are private.
- The public snapshot retains a typed screen projection because callers must render stage-specific data, but it exposes only user-relevant facts, derived financial values, affordances, operation status, and issue codes. React may format values and labels but does not invoke assessment, estimation, totals, stage, or validation rules. Internal revisions, correlation IDs, idempotency keys, and retry bookkeeping are hidden.
- The package has one public Runtime entry point plus a supported browser/React adapter. Public exports are limited to the Runtime factory and contract, user intents, snapshots, and screen projections; an import-boundary test prevents production code from reaching internal paths. The React adapter subscribes through `useSyncExternalStore`, starts the Runtime after subscribing, and owns cleanup.
- Runtime capabilities are injected at composition rather than supplied with each intent. Narrow ports cover draft storage, Plan persistence, report download, analytics, navigation, focus, confirmation, clock, ID generation, and scheduling. Ports return typed outcomes, and the Runtime maps thrown exceptions to typed failures. The report and confirmation ports capture locale-specific presentation dependencies while the Interview core remains localization-free.
- The Runtime is the single owner of durable Interview and Plan facts used by the experience, including draft presence, device-storage consent, Plan presence, and assessment history shown on the result screen. React may retain purely visual state but does not mirror those facts.
- Initialization has an explicit snapshot and hydration barrier. Plan and draft restoration completes before persistence-producing intents run, so defaults cannot overwrite a restored draft during startup or locale reload. The Runtime owns restoration, resume, and destructive-action confirmation policy; the browser adapter owns raw navigation and locale subscriptions and translates them into private environment messages.
- The Runtime serializes messages through one queue. It commits and publishes each synchronous transition before draining private effects on a microtask. Independent port calls may overlap, but their outcomes re-enter the queue; stale outcomes are ignored, and effects are deduplicated by their internal operation identity. Inapplicable or duplicate intents are idempotent no-ops, while domain-rule failures become typed snapshot issues.
- User-initiated Plan saves and report downloads retry only after another user intent. Ambiguous save retries reuse the idempotency key while their source revision is unchanged; draft autosave coalesces newer revisions and retries at the next eligible synchronization trigger; analytics remains best-effort and non-blocking. Durable Plan writes retain persisted idempotency because in-memory effect deduplication does not survive reloads.
- Draft persistence uses an opaque, internally versioned envelope. The Runtime, not React or the storage adapter, chooses among stored drafts and a committed Household Runway Plan. The persisted schema version remains separate from the public TypeScript contract.
- Browser history is a projection, never a second owner of Interview state. Requested destinations and stages are validated by the Runtime.
- One Runtime instance serves one mounted Interview experience. Disposal cancels what ports support, removes adapter subscriptions, ignores every late outcome, and prevents remounts from duplicating persistence or analytics work.
- Migration proceeds behind a facade: establish Runtime contract tests, wrap the existing reducer, move restoration and effects behind the Runtime, migrate draft storage and React, then make old protocol exports private and split internal files. UX behavior does not change as part of this refactor.
- Runtime contract tests cover startup, navigation, validation, restoration and resume conflicts, autosave, persistence, effect deduplication, stale outcomes, idempotency, and disposal. React integration tests cover composition and Strict Mode lifecycle behavior. Focused internal tests may continue to exercise combinatorial stage rules without making internal event or effect shapes part of the supported contract.
- The migration is complete only when React consumes the supported snapshot-and-intent hook; production callers no longer import reducer state, draft internals, operations, effects, events, transitions, or outcome commands; orchestration and Interview calculations have left React; boundary and lifecycle tests pass; and the old protocol exports are removed rather than retained as a compatibility layer.
- This refactor changes ownership and interfaces only. Finance formulas, database and API contracts, authentication policy, draft retention and consent semantics, product copy, and screen flow remain unchanged; persistence-shape separation, visual redesign, and speculative new clients are separate work.
