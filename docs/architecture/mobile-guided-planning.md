# Issue 15: guided daily planning

Implements approved issue #15 / iOS MVP AC09, AC15, AC17, AC18, AC22 and AC23. Reuses #13 native bearer auth, existing gateway/model/rate limits and immutable preview identities, and #14 civil-time/recurrence reads. Apple membership/TestFlight is user-deferred; live-gateway and hosted rollout evidence remain separate delivery gates.

The enabled Assistant opens a three-step flow: choose a day/time zone (horizon), review existing sleep/fixed commitments and describe preparation/travel/meals/care/rest, then enter goals/priorities. Previously entered preferences are retained in account-scoped secure storage, remain editable and can be skipped. Existing calendar commitments and saved priorities are displayed; unknown travel durations or conflicting assumptions are questions, never invented times. User text remains in its original language.

The model returns a bounded schedule proposal or clarification. Server code resolves every existing target/version, computes exact before/after events/tasks/priorities and resulting free time, and rejects overlaps involving proposed blocks, unsupported edits and changes to protected or recurring commitments. Routine additions retain daily/weekday intent and use the established routine command. Existing recurrences are expanded for occupancy but not rewritten by planning.

A new per-owner planner revision advances on relevant shared-record changes, including web writes, so new commitments as well as edits invalidate a pending schedule. Preview storage changes no plan records. Acceptance locks the owner revision, validates the immutable preview, then applies shared task/calendar/priority/routine commands in one transaction. A failed item rolls back all changes and receipts. Operation IDs remain durable across interruption/restart. Rejection/cancellation/AI failure do not change the plan.

Store before/after recovery evidence in persistent planner history. Revert is atomic and conservatively requires the whole owner planner revision to remain unchanged since acceptance; this also protects newly linked references and reminders. Restore edited/removed events and task fields, restore priorities, remove unchanged newly created tasks/events, and withdraw newly created routines through their lifecycle while retaining audit history. Newer changes reject recovery without partial writes. Shared completion Undo remains unchanged.

Apply schema/endpoint before client rollout; roll client back first and retain proposal/receipt/history tables. Tests use approved authenticated command persistence/ownership/rollback boundaries, pure calendar/DST helpers and selective native/browser flows. Cover weekday/weekend/tired-day adjustments, routine preservation, protected commitments, unknown travel, new concurrent commitments, exact acceptance/replay, failed-item rollback, safe recovery, two accounts and AI-off manual use.
