## Bugs corrected

- Failed authentication callbacks linked to a missing error page. They now use the
  existing `/auth/error` route.
- Login redirects lost the requested page/query and omitted several legitimate
  destinations from the safe return-path list. The intended first-party destination
  now survives login; external URLs and API destinations remain rejected.
- Authentication redirects discarded refreshed or cleared cookies. Redirect responses
  now copy the session cookies with their options.
- Anonymous Household Runway analytics were redirected to login. Only the exact
  public event endpoint bypasses cookie authentication; its own validation and rate
  limiting remain active.
- Clearing a task due date could submit a hidden repeat schedule and create an
  unintended series. Submission now requires a due date for recurrence.
- Switching journal dates retained another entry's content and word count. A mood
  change could overwrite the selected entry. The complete selected-entry state now
  initializes together, without overwriting a dirty draft on revalidation.
- Journal mutation controls could act on stale data while a new date loaded or
  failed to load. Those actions are unavailable until the selected entry is ready.
- The desktop calendar extended 224px beyond a 1280px viewport. Allowing the main
  content flex item to shrink removed the overflow. The browser regression waits
  for the actual time grid before measuring the document.
- Long habit names widened the mobile dashboard's habit/task grid beyond its cards.
  An explicit single-column track now constrains the grid below the desktop breakpoint.
  A local browser fixture using the actual compiled CSS measured the cards shrinking
  from 603.21875px to 343px at a 375px viewport. The new authenticated regression uses
  deterministic long-name data; it awaits CI because test identities were already removed.

## Test infrastructure findings

The normal Chromium suite could not collect tests because it imported the separately
configured MCP grant suite. General projects now exclude that profile; its dedicated
runner remains unchanged. Collection was verified for both paths.

Two finance tests shared one account's singleton Plan and ran concurrently. Their
overlapping saves correctly triggered the app's revision-conflict protection, but
failed an unrelated assertion. Running the file sequentially passed; the describe
block now overrides global parallelism without changing assertions.

The account-isolation journey initially failed because the configured backend requires
email confirmation. It passed with temporary identities confirmed through the admin
API. Email confirmation settings were not changed.

The first GitHub browser run stopped before testing: `ubuntu-latest` selected Ubuntu
26.04, unsupported by pinned Playwright 1.58.1. The browser job now explicitly uses
Ubuntu 24.04, matching the [versioned system requirements](https://github.com/microsoft/playwright/blob/v1.58.1/docs/src/intro-js.md#system-requirements).
Browser checks and their mandatory merge gate remain enabled.

## Limits

This is broad automated and browser UAT, not exhaustive coverage of every state.
Live Google/OAuth consent, password-reset email delivery, actual model responses,
external integrations, privileged admin mutations, and OS push delivery were not
exercised. Chat was checked for page rendering, with behavior covered by existing
automated tests. Firefox/WebKit execution, native-device testing, and full assistive
technology review were not performed. Existing Linux screenshot baselines were not
regenerated on Windows. Database migrations were not changed.

After cleanup, automatic approval review declined provisioning another batch of
test identities as unnecessary. The report therefore uses the completed authenticated
runs and targeted reruns rather than claiming a final fresh authenticated suite.
