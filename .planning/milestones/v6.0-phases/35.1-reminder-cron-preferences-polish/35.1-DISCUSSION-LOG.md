| Option | Description | Selected |
|--------|-------------|----------|
| Sequential per reminder, parallel channels | Process reminders one at a time, send push+email in parallel | ✓ |

| Queue-based with worker | Use a job queue for reliable dispatch | |

**User's choice:** [auto] Sequential per reminder, parallel across channels (recommended default)
**Notes:** Simple, predictable, and sufficient for expected reminder volume.

| Option | Description | Selected |
|--------|-------------|----------|
| Log as failed, no automatic retry | Mark failed, log error, move on | ✓ |

| Dead letter queue | Move failed reminders to a separate queue for manual review | |

**User's choice:** [auto] Log as failed, no automatic retry (recommended default)
**Notes:** Keeps v1 cron simple. Retry is a future enhancement.

## Quiet Hours Enforcement

| Option | Description | Selected |
|--------|-------------|----------|
| At dispatch time in cron job | Check quiet hours before sending push | ✓ |
| At scheduling time | Adjust fire_at to avoid quiet hours | |
| Client-side suppression | Let the service worker decide | |

**User's choice:** [auto] At dispatch time in cron job (recommended default)
**Notes:** Simplest approach — no need to recompute fire_at when quiet hours change.

| Option | Description | Selected |
|--------|-------------|----------|
| Defer until quiet hours end | Keep pending, dispatch after quiet period | ✓ |
| Drop silently | Don't send push notifications that fall in quiet hours | |
| Convert to email only | Send email instead of push during quiet hours | |

**User's choice:** [auto] Defer until quiet hours end (recommended default)
**Notes:** User still receives the notification, just delayed. No information loss.
