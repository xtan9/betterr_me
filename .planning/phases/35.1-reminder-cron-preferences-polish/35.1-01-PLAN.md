    - GET without valid CRON_SECRET returns 401
    - GET with valid CRON_SECRET fetches pending reminders where fire_at <= now
    - For each pending reminder: dispatches to push channel (if in channels and not in quiet hours)
    - For each pending reminder: dispatches to email channel (if in channels, email exempt from quiet hours per D-09)
    - Push during quiet hours: reminder stays status='pending' (not dispatched, not marked sent)
    - Successful dispatch: status='sent', sent_at set to current ISO time
    - Failed dispatch (both channels fail): status='failed'
    - Partial success (push fails, email succeeds): status='sent' (at least one channel delivered)
    - Returns JSON with { dispatched, failed, skipped_quiet_hours } counts
  </behavior>
  <action>
    Create `app/api/cron/dispatch-reminders/route.ts` (per D-04, D-07, D-08, D-09):
    - Import: NextRequest, NextResponse, createAdminClient, RemindersDB, ProfilesDB, sendPushNotification, sendReminderEmail, isInQuietHours, log
    - `export async function GET(request: NextRequest)` with CRON_SECRET validation (same pattern as sync-transactions)
    - `const adminClient = createAdminClient()`
    - `const remindersDB = new RemindersDB(adminClient)`
    - `const profilesDB = new ProfilesDB(adminClient)`
    - `const now = new Date().toISOString()`
    - `const pending = await remindersDB.getPendingReminders(now)`
    - Initialize counters: `let dispatched = 0, failed = 0, skippedQuietHours = 0`
    - For each reminder in pending:
      - Fetch user profile: `const profile = await profilesDB.getProfile(reminder.user_id)`
      - Determine quiet hours: `const inQuietHours = isInQuietHours(profile?.preferences?.quiet_hours_start, profile?.preferences?.quiet_hours_end, profile?.timezone)`
      - Determine channels to dispatch: `const channelsToSend = reminder.channels.filter(ch => ch === 'email' || (ch === 'push' && !inQuietHours))`
      - If reminder has only push channel AND in quiet hours: skip (stays pending), increment skippedQuietHours, continue
      - If channelsToSend is empty: skip, increment skippedQuietHours, continue
      - For push channel (if in channelsToSend): call `sendPushNotification(reminder.user_id, { title: "Reminder", body: `Reminder for your ${reminder.source_type.replace('_', ' ')}`, sourceType: reminder.source_type, sourceId: reminder.source_id })`
      - For email channel (if in channelsToSend): call `sendReminderEmail(reminder.user_id, { sourceType: reminder.source_type, itemName: reminder.source_type.replace('_', ' '), date: reminder.fire_at.split('T')[0] })`
      - NOTE: We need the source item name for email. For now, use a generic label based on source_type. A future improvement can join the source table.
      - If at least one channel succeeded: `await remindersDB.updateReminderStatus(reminder.user_id, reminder.id, 'sent', new Date().toISOString())`, increment dispatched
      - If all channels failed: `await remindersDB.updateReminderStatus(reminder.user_id, reminder.id, 'failed')`, increment failed
      - Wrap each reminder dispatch in try/catch for error isolation (one failure doesn't stop the batch)
    - `log.info("Cron dispatch completed", { dispatched, failed, skippedQuietHours })`
    - Return `NextResponse.json({ dispatched, failed, skipped_quiet_hours: skippedQuietHours })`

    NOTE: The cron uses adminClient (bypasses RLS) since it processes reminders across all users. But `updateReminderStatus` currently requires userId matching — this is fine since we have `reminder.user_id`.
