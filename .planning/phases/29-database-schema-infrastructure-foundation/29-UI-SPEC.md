## Infrastructure Artifacts With Future UI Impact

While Phase 29 has no UI itself, it creates contracts that downstream UI phases (31-36) will depend on:

| Artifact | Downstream Consumer | UI Relevance |
|----------|-------------------|--------------|
| `calendar_events` table + `CalendarEventsDB` | Phase 31-32 calendar views | Data model for event rendering (title, color, times, recurrence) |
| `reminders` table + `RemindersDB` | Phase 34-36 notification UI | Reminder channel choices (push/email) shown in event dialog |
| `reminder_defaults` table + `ReminderDefaultsDB` | Phase 36 settings UI | Smart default configuration in user preferences |
| `push_subscriptions` table + `PushSubscriptionsDB` | Phase 34 push permission flow | Subscription state drives enable/disable toggle in settings |
| `profiles.timezone` column | Phase 36 preferences | Timezone display in settings, auto-detected on first visit |
| `public/sw.js` service worker | Phase 34 push notifications | Receives and displays native browser notifications |
| Zod schemas (`calendar-events.ts`, `reminders.ts`) | Phase 30 CRUD API, Phase 32 event dialog | Form validation error messages surfaced in UI |
