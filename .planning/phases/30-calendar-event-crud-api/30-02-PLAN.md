**GET handler** (per D-09, D-10):
1. `const supabase = await createClient()`
2. `const { data: { user } } = await supabase.auth.getUser()` → 401 if null
3. Parse `start_date` and `end_date` from `request.nextUrl.searchParams` — both required, return 400 if either missing
4. `const db = new CalendarEventsDB(supabase)`
5. `const events = await db.getUserEvents(user.id, startDate, endDate)`
6. `const expanded = expandEventsForRange(events, startDate, endDate)` — import from `@/lib/calendar/recurrence`
7. `return NextResponse.json({ events: expanded })`
8. Wrap in try/catch → `log.error('GET /api/calendar-events error', error)` → 500

**POST handler** (per D-02, D-11):
1. `const supabase = await createClient()`
2. Auth check → 401
3. `const body = await request.json()`
4. `const validation = validateRequestBody(body, calendarEventCreateSchema)` → return validation.response if !success
5. `await ensureProfile(supabase, user)`
6. `const db = new CalendarEventsDB(supabase)`
7. Build insert object from `validation.data` — spread all fields, trim title, handle nullables (description, location, color, category_id, recurrence fields)
8. For exception creation (when body contains `recurring_event_id` and `original_date`): include `is_exception: true`, `recurring_event_id`, `original_date` in the insert — this enables "edit this occurrence" (D-06). Add these three fields to the insert only if `recurring_event_id` is present in the raw body (not in the Zod schema — read them from body directly after validation).
9. `const event = await db.createEvent(user.id, insertData)`
10. `return NextResponse.json({ event }, { status: 201 })`
11. Wrap in try/catch → 500
